# Final Project
The final project is an independent project on a topic of your choosing. Projects will be “presented” in class on the final class. Nothing fancy, just a 5-15-minute informal demonstration of what you accomplished along with a brief description of the methods. 

If you are not able the attend the final class session, you may provide a recorded video of your presentation, or I will present your project for you. Your application must run successfully for the presentation.

I must also be able to run your code. You are required to submit your projects prior to the final day of class and the class presentations.

# Project Requirements
You may extend project 1 or 2 and add new features. This is not required though, and if you want to move in a different direction that is fine as well. Prior students have tried a simple radiosity method in the past and developed a scene with a BSP tree – both of these were unrelated to prior lab code.

# Project Ideas
1. Implement planar reflections and/or planar shadows with stencil mapping (OpenGL).
2. Shadows.  Implement shadow volumes or shadow maps.
3. Procedural textures within shaders.  Implement a 3D procedural texture or a noise-based texture (such as an animated flame).  
4. Use vertex shaders to deform a mesh – a good example is to use a texture map storing height values of a terrain.
5. Extend the scene graph to support collision detection and provide animation. Hierarchical animation (e.g. movement of robot arms, hands, etc.) is another idea.
6. Add advanced texture mapping: bump mapping, environment mapping, billboards, multi-texturing effects, etc.
7. Extend the capabilities of the ray tracing software. Ideas: Cook and Torrance lighting/reflection model, distributed ray tracing, or using spatial data structures to speed up ray/intersection casting. Perhaps using CUDA or other GPU computational support methods to enhance ray tracer performance (though this may be dependent on having appropriate hardware).
8. Other possibilities exist with shaders: non-realistic lighting like Toon Shading and improved lighting models like Cook and Torrance are good extensions.

Note that these are not of equal difficulty and some ideas may not merit a full project surrounding them (so you may have to combine a few features).

Also try to be creative with your scene. Having an interesting scene can make the project more fun and give you “style” points.

I will try to assist you if you run into problems, though it may be more difficult since I will not have easy access to code that is close to what you may be trying to do.

# Documentation Requirements
1. A short presentation (5-7 slides) that briefly describes the methods you used within your project. Please include several screen shots (just in case it cannot be run on the computer in class). MS PowerPoint, Apple's Keynote, LibreOffice Impress, and Google Slides are all acceptable formats. I am mostly looking for a brief description of the techniques/methods your project incorporates.
2. Readme File. Please include a brief Readme file with instructions on any menu options or keyboard commands supported. I need to be able to run it on one of my home computers (Windows, Ubuntu Linux, or MacOS).

Please let me know your project idea by the beginning of Module 10. (See here.) I need a short description of what you plan to accomplish.  I want to be satisfied that your project is 1) not so difficult that you risk getting frustrated and spending way too much time, or 2) so easy that you can get it done in a few hours. 

# Grade 

This project is worth 40 points. 5 points will be based on your documentation. Another 5 will be based on the scene definition: it should be creative and properly use modeling transforms and instancing (if you have multiple instances of the same object). The rest will be based on the techniques that you implement. The grading will be somewhat subjective and will take into account the “difficulty” factor. If you attempt something a little more extensive and difficult you will not be punished for some incomplete methods. On the other hand, if your project is a bit easier you are expected to have a more complete integration.

You have about 5 weeks for this project. I don’t expect something that takes every waking minute over that time. On the other hand, this should not be something you start 2 days before and quickly throw together. Budget your time so a “reasonable” amount of effort is given.
